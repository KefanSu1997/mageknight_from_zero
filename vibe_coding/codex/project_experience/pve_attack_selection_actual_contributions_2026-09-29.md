# 攻击按实际来源分配，未选贡献保留

用户手玩反馈：先打出多笔攻击后，无法让一张牌击败第一只敌人，再用横置牌加技能击败第二只。原 `CardCombatActions.Attack` 总是取得并消费全部合法攻击，界面也没有选择来源，因此这是实际入口缺口。

最小修复：新增 `PveBattleSession.AttackSelected(targets, selected)`，经正式 `TurnMachine` 和 `CardCombatActions` 结算。选项必须来自当前池内相同对象引用，拒绝重复、伪造等值对象、已消费、错误阶段及不适用目标；整份选择通过验证后才提交防护和消费。未选攻击保留原实例。旧 `Attack` 仍全选，保留历史调用的行为。没有拆分单笔数值，也没有修改原卡数值、抗性、城防、击杀奖励。

后台验证：`AutomationOutputs/RulesState/20260929_233355_80358625`，新4项＋既有5项 session 直接受影响回归，共9/9。实际原怒火强化4单独击败原032，原横置1＋阿瑞希亚炽热剑术2再击败另一原032；原费用、已出牌引用、已发生伤牌、名望与剩余攻击守恒。另验证重复/伪造/空来源拒绝、限定敌人及远程/攻城未选保留。

场景核对发现初版测试的玩家名称误写诺洛瓦斯，未填 HeroId，直接追加了属于阿瑞希亚的 pool000:02。正式 UI 正确拒绝把诺洛瓦斯重整用于战斗。已将对应测试明确为阿瑞希亚 HeroId、名望3的合法等级2，并经 `HeroSkillAcquisition.Acquire` 取得自身技能；击败两名原032后名望为7。只补该单方法，不改生产规则或其他已通过测试。
