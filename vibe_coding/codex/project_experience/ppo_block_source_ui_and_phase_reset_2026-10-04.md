# 格挡来源UI与真实阶段悔棋

策略后台支持逐来源消费时，Demo必须提供同一正式API的输入入口，否则后端能保留贡献，界面却一次吞掉所有来源。保留选择按BlockAllocation引用、按实际敌人/攻击槽过滤，与同值不同物理来源隔离；预览与提交均复用PveBattleSession正式接口，不能用UI求和代替元素/迅捷规则。阶段重置恢复旧实体后必须清掉旧来源引用选择。

主界面原96高的两行预览缩到60后，原字体中文行高会造成截断，即使缩短文字仍不足。真实场景断言保留失败；改为一行当前攻击/有效值/需求，完整不足规则留在面板。不能用isTextOverflowing=false或删断言掩盖。

实际53点击场景：Tovak原决心强化5、寒冰护体基础冰3、行进横置物理1对双原032；先5保留4、恢复阶段返原牌/蓝晶、再分别消费5与4，正式防御双已格挡且零伤。两次截断失败与最终通过分别保留。本用例证明指定UI操作，不是通用PPO/全卡/全战斗胜利。证据见 `vibe_coding/codex/worklog_2026-10-04_ppo_block_source_ui.md`。
