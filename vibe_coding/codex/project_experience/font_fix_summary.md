# 字体问题修复复盘

## 背景
- 在自动化运行 DeckManaTest 场景时，原始 TMP 字体缺失汉字，导致按钮文本显示不完整。
- 场景自动化工具需要稳定的 UI 文本渲染，以便截图和报告具有可读性。

## 处理过程
1. 调研 Unity 项目中现有字体加载逻辑，确认主要依赖 TMP 静态字库。
2. 编写 `Assets/Editor/FontTools/DynamicFontGenerator.cs`，在菜单 `Tools/Fonts/Generate Dynamic MSYH Font` 下生成可在运行时动态扩展字符集的 TMP 字体资产。
3. 在 `Part1SceneHarness` 中优先加载动态字体，保留原始字体作为兜底，保障旧资源链路可用。
4. 通过自动化配置 `AutomationConfigs/part1_deckmana.json` 回归验证，确认新增字体资产后控制台仅剩首次导入提示，截图文本正确。

## 经验
- 在 UI 自动化测试中，文字资源质量直接影响报告可读性和后续判定，应优先确保字体资产完备。
- 利用 Unity Editor 扩展创建工具菜单能快速复用操作流程，降低团队成员手动配置成本。
- 动态字体在多语言环境下比静态字库更稳健，可结合 Resources 目录确保运行时加载。

## 教训
- 在迭代 UI 自动化前应对资源完整性做初步巡检，避免在测试阶段才暴露缺字等基础问题。
- 对于会影响多个场景的底层资源（如字体、材质），需要同步更新运行时加载逻辑，否则资源虽生成但不会被正确引用。
- 首次引入新资产应记录生成步骤（脚本位置、菜单路径），方便后续重建或复现。
