# 原卡目录、打包法术与连续消费者

- `CardsAssets` 包含旧的三个空白高级行动槽和一张牌背；统一目录应复用 `tools/audit_card_sources.py` 的有效原图结论，不能把125条资源等同121张有效卡，更不能改验收预期来凑数。
- 打包场景需显式传入原 `SpellCardSO` 上下半费用/原文。Action描述中的颜色无法表达下半黑费和额外费用，不能替代 `SpellCardData`；缺元数据时应拒绝，不猜测或免付。
- PVE入口要把本场实际敌群数量交给正式Context，否则按敌数加成的原效果存在但数值始终错误。
- 选择分支超过六项需要分页，按钮高度要覆盖TMP实际行高和边距；只调fontSize不保证文字可见。实际截断检查及关键截图能发现空白翻页按钮。
- 同一连续路线可合并验证原上半费用/元素、白昼拒绝下半、混合格挡、蓝加蓝整笔拒绝、牌区及跨回合守恒。失败保留成功区间，前缀仅重放以恢复真实状态，补失败尾段；不得重建战斗快照充当回合。
- 目录绑定、有部分操作、后台通过和最终场景通过分别记录，不把22种有入口写成22张全规则通过。
