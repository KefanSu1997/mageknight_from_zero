# DeckMana 桌面视觉改版经验

## 视觉结构
大块互相竞争的背景色会让测试页面压过卡牌。此次使用统一的深青石板背景、古铜细线与暖白文字，将五种魔晶的颜色限制在小图标内，保留卡牌正面的对比度；背景装饰集中在边缘，中心为真实交互留白。

新增 DeckManaTableView 仅接管牌库+魔力组合，通用 Harness 保留其他系统测试。1920×1080 设计坐标配合 CanvasScaler.Expand；所有装饰图像关闭 raycastTarget，只有按钮和滚动区域接收指针。

## 绑定与状态
- UI 重做应保留自动化按钮路径，避免视觉改版同时破坏验收配置。
- Part1TestManager.SetupUI 默认给六个按钮注册事件；没有显示的按钮仍需保留隐藏绑定，不能随意传 null。
- 浮窗空状态依赖预览标题的字体；隐藏源绑定仍需完整设置。
- 空手牌槽位不能放在 handRoot 内，否则 HandManager 会将装饰当成手牌参与布局和数量计算。使用兄弟节点，按实际 handRoot 子项数量切换。
- 旅途手记是控制器原始日志的展示层，只过滤已知初始化噪声；未知错误原样保留，Console 完整诊断不变。仅在文本变化时刷新滚动布局。

## 验收
配置：AutomationConfigs/part1_deckmana_table.json。

第一轮检查了 7 个状态，发现辅助文字偏暗和英文测试输出影响画面；调整后加测重新抽牌与非空弃牌浏览，10 步成功。截图可见初始牌组 20 张，首次抽牌后 15 张，再次抽牌后牌组 10 张、弃牌 5 张、手牌仍 5 张。

原始输出：AutomationOutputs/DeckManaPolish/20260909。图片和提示词：vibe_coding/codex/deckmana_table_image_prompts_2026-09-09.md。素材通过内置 image_gen 生成，原图复制入 Resources，不引用用户目录中的临时输出；没有通过脚本修改图片。

纯色保护和点击成功只能证明最低流程可用，仍必须打开初始、操作后、有卡牌浮窗和空浮窗截图检查构图、字体、层级，再直接点击 Game View 验证鼠标命中。
