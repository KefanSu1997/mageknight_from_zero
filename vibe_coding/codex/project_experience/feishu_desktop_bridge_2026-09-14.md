# 飞书私聊到桌面任务接入

- 用户已允许的权限不擅自收窄；权限齐全、订阅事件、发布和实际接收进程是不同步骤。针对缺失步骤修复。
- 接收文字事件为应用身份 `im.message.receive_v1`。长连接只表示传输就绪，必须用真实私聊和回复验收。
- 独立 Codex app-server 不能接管桌面正在持有写入锁的任务。不要杀桌面、绕锁或复制项目写入；复用桌面自带 App Tools MCP 的 send_message_to_thread/read_thread。
- wait_threads 不能等待调用任务自身；本机桥接使用低频、当前单轮摘要读取，只回传最终文本，不传工具输出或完整轨迹。
- 中文配对字符串不能直接传给 secrets.compare_digest（只接受 ASCII str）；编码为 UTF-8 bytes 后比较。配对码在短时重启之间保留到期时间。
- 本机密钥用 DPAPI；安装独立 SDK 环境，避免与全局 websockets 主版本冲突。后台启动使用隐藏窗口。
- 配对过期/不匹配不能静默忽略，必须异步明确回复；复制的格式化文字可能作为 post 发送，需要兼容平铺与语言包装的正文以及不换行空格。记录接收时间/类型而非完整事件，可区分传输与配对问题。
# 任务进行中的补充消息（2026-09-15）

单一 worker 派发后同步等待桌面最终回答，会使后续用户澄清一直停在 queued。接收成功和转交成功必须分别记录；等待循环应继续转交用户补充并立即确认，用条件状态更新避免重投。只恢复已证明确实送达的原指令到等待状态，不自动重放未知执行结果。修复后通过真实三条积压消息进入桌面原任务及飞书回复 API 成功验证。
