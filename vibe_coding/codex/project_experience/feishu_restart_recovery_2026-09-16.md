# 飞书桥接：重启、版本更新和离线消息恢复

- 故障：Windows 更新后没有桥接进程，旧 status.json 却仍保留 connected=true；之前只从任务终端临时启动，没有登录自启。离线消息没有进入 SQLite，不是用户手机发送失败。
- Codex 的 Node 路径、插件版本和命名管道随更新/会话变化。读取当前已安装组件和现存管道，并用只读 read_thread 校验任务目录；不能沿用写死版本或旧管道。只使用桌面工具转交，不绕过任务锁。
- 使用当前用户 Startup 快捷方式启动隐藏 pythonw 守护程序；单实例本机端口，子进程退出后 30–300 秒退避重启。计划任务在本机实测启动失败，已撤销本次新建任务，不能把注册成功当成启动成功。
- 桥接重连后只补收已配对私聊、已配对用户的文字，最多 7 天、每轮 250 条；message_id 去重，机器人/其他用户/撤回消息排除。超过上限或 API 失败必须留出失败状态，不能假装补收完整。
- 桌面尚未打开：保留待转交指令，回复一次等待说明，低频检查恢复；正在执行但结果不明的消息只通知中断，不自动重跑。已明确转交的消息可人工设 waiting，仅续等结果。
- 状态应区分飞书连接、桌面可达、队列和心跳新鲜度。进程退出时清除 connected，不能凭昨日状态文件报正常。Hello/Hello?/Hello？作为无模型健康检查。
- 验收分层：本地测试、真实离线补收、原任务出现指令、回复 API 成功、手机实际看到回复、守护恢复分别记录。不得用前几项代替全部通过。登录快捷方式没有通过真正重启验证时，明确说明。
- 仅当前用户登录且电脑开机时工作；不承诺电脑关机/睡眠时实时收发。不修改 VPN、Windows 更新或防火墙；不上传截图、日志。
