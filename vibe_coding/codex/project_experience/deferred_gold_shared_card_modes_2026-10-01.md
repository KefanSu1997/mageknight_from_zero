# 金色延迟付款、原模式分层与免费强化许可

1. UI 取金骰若先传基本色，会永久丢失通用身份。保留原骰引用与 Gold 库存；在正式原子付款规划中按当次真实基本色费用使用，仍检查昼夜与例外许可、黑费及支付失败守恒。付款后规则钩子记录费用颜色，不记录 Gold。
2. 多颜色原卡不能用「基础红/强化红/基础蓝/强化蓝」混排。共享模式入口按原 `Enhanced` 字段过滤，再显示当前层选项；标题、说明、费用和确认文案对应同一原选择，战外与输入窗口必须一起覆盖。
3. 分层改造不能仅过滤已有目录。凝结与全神贯注的原强化实现虽在后端，原选择列表缺入口；补原定义入口并测试实际下一张消费者。
4. 免费强化原许可应按执行前状态消费，不能以 UI 是否显式点击强化决定是否清除。注意产生新许可的凝结本身不被误清除。
5. 原随机构筑在回合/轮次入口会重置源骰；固定测试必须核对最后实际种子与源面。测试后恢复原构筑字节与哈希，不把临时种子留给试玩。
6. 场景补验的最后退出按钮失败，不应废弃前面真实消费证据。保留 failed 报告，必要前缀只重放状态，补失败后缀并独立记录。
