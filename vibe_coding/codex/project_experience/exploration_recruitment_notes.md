# Part1 探索与招募测试经验

## 背景
- 为 `Part1_ExplorationRecruitmentTest` 场景补齐玩家视角要素，涵盖探索地图与招募演练。
- 目标是对齐 DeckMana 测试场景的完成度：按钮驱动、日志反馈、自动化脚本。

## 关键经验
- **探索队列**：使用 `Queue<AxialCoord>` 维护下一批待探索坐标，结合 `HashSet` 去重，可循环演示而不触发 `TilePlacementService` 的重复放置异常。
- **地图可视化**：UI 内动态生成六边形节点时，以轴坐标换算成 2D 坐标再居中，可以避免依赖额外 prefab；给当前地块做颜色高亮，利于辨识。
- **招募面板**：同步维护候选池、已招募列表与指挥槽状态，任何成功/失败都即时刷新 UI，配合日志输出方便回放。
- **位置上下文**：探索结果驱动 `RecruitLocation` 更新，再推送当前可招募单位，能让玩家理解探索与招募的因果关系。
- **自动化验证**：短流程（两次探索 + 一次招募）即可覆盖主要 UI 变化，默认等待 0.7~0.8s 能捕捉截图且避免日志未刷新的问题。

## 后续建议
- 如需演示更复杂的探索形态，可在队列空时延迟清表，而非立即重置整张地图，让玩家可以回顾既有地块。
- 可以把招募池改为配置化数据，便于后续扩充不同场景的招募示例。
