# DeckMana 交互反馈与手牌可视化记录

## 问题背景
- 牌组/弃牌区在新版透视桌面里仅剩装饰元素，缺少点击反馈，用户难以确认是否触发预览。
- “测试魔力池”按钮与背景色差过小，虽然可点击但几乎不可见。
- 抽牌后手牌区域只剩日志提示，实际卡牌因为贴图加载失败或遮挡没有显示。

## 解决套路
1. **建立统一的点击反馈组件**
   - 新增 `DeckUiClickFlash`，在按钮子节点放置 `CanvasGroup + Image` 作为高亮层。
   - 通过 `PlayFlash()` 协程完成快速淡入淡出，突显交互完成。
   - 在 `Part1TestManager` 保存引用，点击牌组/弃牌按钮时触发闪光并打开浮窗。

2. **让测试按钮自带主题感但保持可读性**
   - 为按钮底板补充 `Shadow` + `Outline`，避免与透视桌面混在一起。
   - 图标背景挂 `DeckUiGlowPulse`，持续脉冲强调可交互元素。
   - Label 上仍保留原文案，颜色统一用浅色以匹配主背景。

3. **手牌区域的可视兜底**
   - 在 `CardRuntime.Init` 中预先将 `artwork` 设为 Deck 主题卡背，确保初始即有可视内容。
   - 当异步载图失败时打印警告并维持卡背，防止出现空白卡牌。

## 经验
- 复杂主题场景里，按钮需要额外的高光或描边，避免被背景大图吞没。
- 牌堆类交互最好附带“点击查看”等字样，降低回访用户的记忆成本。
- 任何依赖异步资源的 UI，都该提供视觉兜底（占位图或进度提示），保证在资源缺失时仍可操作。
- 自动化截图要与实际表现一致时，优先复用场景主摄像机的后处理配置，并让截图脚本按名称检索专用摄像机，避免抓到默认空场景。
