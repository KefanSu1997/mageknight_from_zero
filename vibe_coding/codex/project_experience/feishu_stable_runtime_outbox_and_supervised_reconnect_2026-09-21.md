# 飞书：独立运行目录、持久回复及有确认的续接

## 故障证据

重启后只有守护进程及其venv启动器，19572被占用，19571没有桥接；启动快捷方式引用Codex包的LocalCache下venv，代码却用普通LOCALAPPDATA保存状态。工具看到的service/status仍是9月18日。旧飞书日志确有127.0.0.1:7890代理不可用，但不能以旧日志断言本次的唯一原因。不要仅凭进程存在或旧connected=true汇报正常。

## 最小修复

- `tools/feishu_runtime.py`统一使用用户目录 `.mageknight-feishu`，不依赖打包应用与Explorer不同的LocalAppData视图；DPAPI、SQLite配对/去重和历史水位保留，旧文件保留。已有venv本地复制约83MB，没有安装或下载依赖。
- `feishu_setup.py`、守护、健康检查复用相同运行目录；登录快捷方式指向独立目录中的pythonw及项目守护脚本。桌面工具Node组件增加实际包目录查找，在清除继承的Node/命名管道环境变量后真实连接成功。
- 只在桥接进程NO_PROXY中加入飞书域名，不修改VPN、系统代理或其他域名。飞书HTTPS直连200、真实长连接和消息发送成功均分别核对。
- 守护检查每次启动的instance、控制线程独立heartbeat和工作线程活性；过期/线程退出/持续离线时只回收自己创建的桥接子进程树并退避拉起。普通状态更新时间不能代替独立控制心跳。90秒初始宽限、180秒心跳超时、300秒持续离线阈值；退出后30至300秒退避。
- 回复先进入SQLite outbox；API成功后才标记sent、清文本、记last_reply。网络/API失败保存pending及下一次重试时间；重用同一个UUID防重复，30至300秒退避。已完成操作的结果发送失败不能把用户指令丢弃或重新执行。
- 桌面明确确认转交之后将指令记为waiting；桥接重启/桌面暂时断开只续等原任务，不重发指令。未确认的running/dispatching继续明确提示中断。修复resume模式错误跳过同一已完成任务、无限等待的问题；已终止的桌面任务仍需提示，不能作为连接故障无限续等。
- `tools/feishu_health.py`按实例、心跳新鲜度和线程状态计算在线，不暴露凭证。
