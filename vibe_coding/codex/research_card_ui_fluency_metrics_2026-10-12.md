# 卡牌游戏 UI、操作流畅度与 RL 优化指标调研

调研日期：2026-10-12。以官方功能说明、开发者访谈、原论文及作者工具为依据；下文项目方案与奖励公式为设计建议，尚未实现或进行体验验证。

## 结论

建议采用“对象直接操作 + 可修改的操作计划 + 公开结果预览 + 明确提交边界”。简单无歧义动作走短路径；有真实策略选择的费用、材料、目标和贡献保留选择。优化的是在同等游戏意图与正确结果下的交互负担，不能用胜率、点击少或结束快分别替代流畅度。

现有 PPO 玩家决定怎么游玩；玩家训练本身不会修改 UI。界面打磨需要另一个外层过程：提出 UI 版本、用固定意图测试和实际游玩评估、通过规则一致性后比较指标、再修改。若以后训练自动界面优化器，它的动作才是布局、步骤组织、默认值或动画设置。

## 对《魔法骑士》的具体设计建议

1. 固定位置显示当前阶段、资源、已选实体和待完成义务。面板重绘不应造成按钮身份或位置无故变化。
2. 选牌后就近呈现基础/强化/横置。无需目标/材料且无其他义务的情况保持短路径；复杂选择采用同一个明确的准备区域。
3. 准备区域展示“牌本体、模式、目标、费用、材料、预计贡献”。逐项修改应保留其他仍有效选择，避免付款失败后从头开始。
4. 提交按钮明确显示还缺什么；无效操作的原因关联到具体字段，方便一次修正。
5. 只对原规则允许、结果已公开的部分做确定性预览。随机效果显示不确定性，未来牌序等隐藏信息不进入预览或actor。
6. 自动选费/选贡献应区分无策略歧义的唯一选择与真正有成本差异的选择；后一类需预览、覆盖入口或显式确认。
7. 决策反馈优先出现；动画呈现可配置速度，测清哪些时间真的阻止下一步输入。不能为更快而漏反馈或改变规则顺序。
8. 操作计划撤销、演练阶段重置和正式原规则下的回退是不同功能，UI和统计均分开。

## 衡量单位：语义意图

例如“同一物理卡的强化攻击，用同一付款来源，攻击同一目标，消费同一组贡献”。界面A与B的操作路径可以不同，但必须达到相同正式结果、费用和实体去向。

测试任务从基础出牌、强化付款、单/多目标、材料选择、贡献子集、错误恢复、轮末义务等正式实际入口选取。各任务需已知实际入口与前后预期；初始可解性未知的整战不能随意标为UI不可用。固定任务与玩家自主游玩两组证据分开。

## 可自动记录的指标

| 指标 | 建议定义 | 用途与解释边界 |
|---|---|---|
| 意图完成率 | 预定意图正确完成数 / 全部尝试数；超时、未映射、失败保留 | 主门禁；不能只算成功子集，也不是整战胜率 |
| 交互冗余 | 实际操作数减去同任务已验证参考操作数；分报点击/拖动/键盘 | 短路径目标；参考不是已证明全局最短，真策略选择不是冗余 |
| 面板切换负担 | 完成一意图所需逻辑面板/模态切换数及最大深度 | 避免依赖隐藏功能；重绘不算切换 |
| 拒绝与恢复成本 | 实际规则拒绝、修正后完成所需额外操作/时间、保留选择比例 | 区分规则错误、策略误选和UI输入错误 |
| 可用入口缺口 | 已知合法可完成意图却无对应UI入口的任务数 / 已检查任务数 | 独立规则诊断，不把合法性oracle隐藏到actor mask里 |
| 输入确认延迟 | 输入被接收至首个明确视觉反馈，P50/P95/P99 | 测UI响应；不是模型推理/桥接/人为等待时间 |
| 下一步阻塞时间 | 界面接受本步后，下一步必要操作无法输入的累计时长 | 识别动画和过场负担；真实规则等待分开 |
| 重复无进展状态 | 相同意图内重复“正式状态+计划+当前面板”，无新信息或正式进展 | 可以发现循环；不直接把考虑不同计划或撤销当循环 |
| 布局稳定性 | 同一角色控件因无关更新移动、消失/重现的次数 | 对熟练操作和手部记忆有帮助，亦需真人校验 |
| 指向负担 | D/W与指针路径，或经真人标定的Fitts预测时间 | 合成瞬移点击无法代表人类真实指向耗时 |
| 预览/结果一致性 | 可确定公开预览与实际正式结果的差异 | 规则/UI一致性门禁，不能以改善点击数抵消错误 |

无进展状态指纹应包含资源、牌区、目标与材料选择、待办义务、实体消费和当前逻辑面板；排除时间戳、累计拒绝计数等噪声。不宜直接采用现有观察version，因为一次拒绝可能改变计数，掩盖语义上的循环。

## 相关研究与人类评价

| 工作 | 支持什么 | 不支持什么 |
|---|---|---|
| Card/Moran/Newell，KLM，1980 | 把已知操作方法分解为输入、指向、准备和系统响应；适合估计熟练用户例行执行成本 | 不预测复杂卡牌战略思考、初学者学习或所有误操作 |
| MacKenzie，Fitts法则综述，1992 | 距离与目标尺寸影响指向时间；比较布局与点击区域 | 不能把机器人瞬移点击的耗时当成人类性能 |
| Pinelle/Wong/Stach，游戏可用性启发式，CHI2008 | 游戏特定的控制、反馈、一致性和信息清楚性检查框架 | 启发式检查本身不是已标定RL奖励或直接体验分数 |
| Phan/Keebler/Chaparro，GUESS，2016 | 游戏体验满意度，多维度而不是仅效率 | 不可把整份满意度量表缩成每次点击奖励 |
| Vanden Abeele等，PXI，2020 | 区分功能体验和心理体验；本项目重点关注易控制、进度反馈、目标/规则清晰度 | 模型概率、奖励或短路径不能替代玩家回答 |
| Hart/Staveland，NASA-TLX，1988 | 测主观脑力、身体、时间负担、表现、努力和挫败 | 卡牌战略思考也会产生负担，不能将TLX高直接归因于UI |
| Todi/Bailly/Leiva/Oulasvirta，CHI2021 | 用预测HCI模型和model-based RL做保守UI适配，计入适应/重学成本；公开代码 | 菜单优化结果不能直接外推复杂卡牌游戏；不是本项目PPO实现的现成替代 |

## RL目标建议

先把所有指标作为独立评估日志，确认测量有效后再引入奖励。优先分三层：

1. 硬约束：原规则、费用材料、实体身份和生命周期正确；入口与输入语义不丢失；无崩溃；隐藏信息不泄露。
2. 主任务：完成规定操作意图/完整原游戏目标。UI版本比较时先要求任务完成率没有恶化。
3. 交互成本：冗余操作、无效模态切换、输入阻塞和错误恢复成本。不能鼓励少出牌或跳过复杂功能来刷效率。

局部“完成既定意图”的UI导航课程可以考虑：

`R = C * success - C * failure - bounded_ui_cost`

其中每个任务的总ui_cost限制在[0,1]、C>1，让完成意图始终优于立即失败；step limit仍算未完成。该公式是项目提案，不是文献验证的最佳权重，不直接替换完整战斗PPO奖励。

完整战斗PPO应保留原目标，UI成本先作为小的、受预算限制的附加项，并独立保存raw reward。不要继续把“进入下一阶段”单独当成流畅度正奖励，不一律惩罚撤销，不奖励按过一个按钮。关键是实际提交并满足正式后置条件。

若训练UI优化器，则外层奖励取固定测试包的完成率与交互成本，并加布局改变/重学成本；不要在一局里随意移动按钮。CHI2021的保守适配思想可以借鉴，但建议本项目先比较离线固定A/B版本。

## 现有项目能复用什么、还缺什么

可复用：action→实际控件→EventSystem命中→正式前后状态、原文与向量签名、训练与冻结/脚本角色区分、原始失败轨迹。

需要补：intent_id及明确成功/失败事件，逻辑panel_id，输入接收/反馈可见/下一步可操作三个时间戳，动画阻塞原因，取消/恢复事件类别，同意图参考路径，界面版本与原规则/数据SHA绑定，成功及全部失败分母。

现有UI pilot的elapsedSeconds包括0.15秒人为稳定等待，文字编码推理/文件交换也不是游戏输入延迟。本次只提出埋点合同，没有重跑训练或改UI/奖励。当前主训练已有CUDA/SB3入口，应沿用其上游训练核心；这些指标可接到环境与诊断层，不另写PPO算法。

第一批建议测试：基础/强化出牌、同名物理实体选择、指定来源付款、选材料、贡献子集分配、错误后保留计划、跨阶段点数失效提示、回合末义务。采用相同语义意图比较界面A/B，再用真实连续游玩和少量真人校验。
