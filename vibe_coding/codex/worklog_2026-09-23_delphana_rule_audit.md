# 黛尔法纳大师：接入前纠正激活与格挡模型

用户游戏期间的轻量核对；没有启动Unity、编译或测试。大师仍未开放加载，既有19/30部队有限场景覆盖不变。

## 来源与已确认约束

- 原图：`Assets/GameData/cards/army_en_005.png`。四色能力的实际文字和费用以此为准；红色是目标若成功格挡则消灭，不能改写为无条件消灭。
- [Lost Legion原扩展规则第5页](https://www.mageknight.net/wp-content/uploads/Mage-Knight-Board-Game-Expansion-The-Lost-Legion-Rules-2013.pdf)：首次能力令部队耗竭，此后未受伤时仍可追加魔力使用不同能力，每项只用一次；仅可交涉招募，不能免费取得或成为战斗号召目标。
- 本地`resources/rulebook/rulebook_chinese.PDF`第24页：多次攻击敌人须全部攻击成功格挡，才算敌人被成功格挡。停攻、取消攻击不等价。
- 本地规则第8页、原图元素标识：蓝色非攻击效果须检查冰抗，红色须检查火抗；大师四能力均须遵守奥术免疫。牌面弓/盾图标具体允许阶段仍须用原教学规则确认，不能仅凭通用“额外战斗效果”推断。

## 从实际源码得到的接入边界

1. `CardUnitActions.ApplyAbility`当前每次都检查`CanActivate`并耗竭。不得通过临时`Ready()`再调用来伪造大师后续能力。需要记录真实部队实例的本次激活及已用能力，后续费用不足/目标不合法时保留先前已完成结果。
2. 取消原拟“一次多选四能力并统一付款”的强制方案。按能力逐次选择目标并付款；每次操作自身须付款前校验完整，不能因后续能力不合法回滚已经生效的合法能力。
3. `PveBattleSession.Block`目前先保留格挡分配，`BattleResolver`才写入`SuccessfullyBlockedAttacks`。红色条件必须进入正式结算，不能用UI选择或未结算计划冒充格挡成功。
4. `ActionContext.WasBlockedThisBattle`目前由某次攻击成功便记录，不能直接用于大师“全部攻击格挡”判断。先保留该旧语义，新增需求按实际攻击槽核实，不为大师顺带改写所有旧消费者。
5. 条件消灭绑定原敌人实例，兼容远程移除后的索引重排；由正式击杀路径结算名望/战场结果并清理本场许可，避免重复发奖。尚未修改这部分代码。
6. UI保留选部队→能力→目标→确认；首次使用后的已耗竭标记应保留，同时展示仍可合法使用的不同能力。受伤或销毁后不可继续。

## 下一批最小验证范围

- 同一真实大师先用一种能力、再用另一种能力，对相同/不同真实目标；每次实际付款、仅首次耗竭，重复能力拒绝。
- 第二能力无费用/目标无效时，第一能力结果和资源保持；已受伤后不得继续。
- 四项主要消费者：停攻后不受该敌伤害、减甲后实际攻击、去城防/抗性后实际攻击、完整格挡后消灭及名望。
- 同敌多攻击只挡一项不触发消灭；全部真实挡住才触发；取消或停攻不触发。
- 正常招募入口与禁止的免费取得/供应借用；分组测试原免疫，不扩大为组合穷举。
- 后台通过之后纳入连续场景；本记录没有新增通过结论。
