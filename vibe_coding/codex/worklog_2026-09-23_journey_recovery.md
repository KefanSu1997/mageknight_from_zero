# 连续旅程的原手牌、治疗与部队重整入口

## 修改思路和功能

之前连续旅程只有选敌群和战术入口，很多原卡虽然有正式效果，却无法在战斗前使用。本批新增 `PveJourneySession.PlayOutsideBattle/HealOutsideBattle`，在同一实际玩家、进行中回合及同一 ActionContext 上调用正式 CardPlayActions、ActionSystem 和 CardHealing；不建立假战斗来提供阶段，也不重建牌库或部队。

新增战斗外手牌面板 `PveBattleController.JourneyHand.cs`：分页点选实际手牌→选择原效果→点选实际自有部队→确认出牌。原文、原图来自已绑定 CardSO；治疗英雄和治疗部队分别消费真实治疗池，单位费用仍按原等级。重生支持多部队目标；其他目标入口限制单支，原效果继续做等级、状态、费用和总等级校验，失败不先扣费。原目标参数调用后恢复，避免下一张卡继承上次目标。

新增8种行动/法术的部分或全部恢复相关分支：宁静、大地之子、活力焕发、提神漫步、再生、能量流转/能量窃取、痊愈/感染、复原/重生。战斗入口另开放大地之子的原格挡和感染战斗分支，数值仍在原效果中。结合上一批目前30种行动/法术 Id 有至少一个明确分支，不代表30张全分支均完成或场景通过。

战斗前及战斗结束后都可打开恢复面板；进行中的战斗不提供此入口，后台也拒绝。原场景仍保留神器/技能/部队已有恢复功能。选择手牌、补血和重整均不擅自占用战斗行动；是否允许及如何消费由原规则负责。

## 实际集中连续场景

生成器 `tools/build_pve_journey_recovery_acceptance.py`：81步/127断言。`AutomationOutputs/PveBattle/20260923_041902_b67666b2` 全通过。

1. 用原目录选择7张手牌和1支农民，既有起点绿晶1，取得原捷足先登。战斗前活力焕发基础选绿，实际给绿色临时魔力，卡入已打出。
2. 面对原攻击4/护甲3的哨卫；农民发动格挡2耗竭，但未完成格挡。实际分配农民承伤：单位护甲3后获得创伤1，剩余伤害1由英雄承受，产生手牌伤1。本场未击杀敌人，正式结束战斗，保留同一敌人。
3. 原再生强化指定这支耗竭受伤农民，优先消费刚生成的绿色临时魔力，库存绿晶仍1；得到治疗2，农民就绪但仍有创伤，仍不能发动。治疗单位按原等级1花1点，再用余下1点治疗英雄手牌伤，二者创伤都为0。
4. 正式结束回合，手牌5、单位状态保留。新回合试图对已就绪农民用能量流转，被拒绝，绿晶1和手牌都不变。
5. 再战上一场同一幸存敌人，农民实际再次发动格挡2，两张原牌各横置1，合计4挡住攻击4，不再受伤。原狂怒强化支付红晶得到攻击4，击败护甲3，名望2。
6. 战后用仍保留的能量流转指定当前耗竭农民，支付原绿晶1，实际重整；结束第二回合：手牌仅宁静、弃牌6、英雄/部队无伤，农民就绪、红绿晶0。

关键截图已查看。视觉检查另外发现TMP自动字号默认上限导致简短提示放大过头，以及伤牌显示空框：限制字号上限为23/21，伤牌复用既有战斗文本表现（当前仓库没有独立原伤牌图可绑定）。仅重放到第44步，补原选牌/治疗状态两项显示检查；后续报告及最终Console路径在 `pve_journey_recovery_acceptance_index.json` 中记录。完整81步规则证据不重跑。
