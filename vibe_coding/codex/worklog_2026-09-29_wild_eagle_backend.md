# 野性盟友 / 神鹰之眼后台（2026-09-29）

## 原文核对纠正

来源 `Assets/GameData/BattleDemo/original_skills.json`：
- 001:01 野性盟友：`探索的移动费用降低1点。每回合一次：攻击1，或者一个敌人的一次攻击降低1点。` effects[0].effect_freq 为常时。
- 004:02 神鹰之眼：`每回合一次：移动力1。此外，黑夜中，探索费用降低1点，白昼时，你可以在2格距离翻开城防地点中的守军。` effects[1].effect_freq 为常时。因此审计文档中“神鹰夜晚当回合许可”的建议不准确，应以原文为准：夜晚减费和白昼距离是拥有即可用，不必先发动移动。

## 实现

- 新 `ExplorationService.Cost(player, context)` 同源计算验证与实际支付；野性持有者减1，神鹰持有者实际黑夜再减1，最低0，不随主动次数清除或累加。
- 野性实际主动只给一次攻击1或对实际敌人实际攻击槽 -1；复用实例绑定/真实承伤消费者，不写全局攻击减值。Loader 对此被动开头原文单独标主动 OncePerTurn，避免错误 Unspecified 拒绝。
- 神鹰主动在合法行动前获得移动1。SiteVisibility 按实际白昼与持有技能把堡垒/法师塔/城市可揭示距离提高到2；实际地点揭示保存原守军引用，无临时克隆。
- 不再由两技能写入旧 ExploreMoveDiscount / CastleRevealRange 悬空值；常驻直接读取当前持有技能，移除持有关系即不适用。

## 重要地图限制

现 MapTile.cs 自述“简化示例仅记录边缘地形”，一对象占一个坐标。ExplorationService 原 ProcessTileEvents 仍随机30%生成怪物，并非原版7格板块固定要素。此次后台既有探索服务测试只能证明费用/抽堆/原实体放置正确，不能作为原板块拓扑或完整探索验收。已告主代理，需要正式原板块接入或明确保留缺口，不造一个平地格子冒称原板块。
