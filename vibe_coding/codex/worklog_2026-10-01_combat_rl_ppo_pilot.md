# 2026-10-01 战斗 PPO 闭环与实测

用户要求：用实际低维状态学习获胜策略，建立 UI ↔ 状态映射，帮助探索测试；确认本机算力与速度。用户随后明确最终训练采用 PPO，已执行，本批没有交付 Q-learning 策略。无修改正式游戏逻辑和 UI，无 packages 安装、远端下载、上传、推送、VPN 或系统操作。

## 完成内容

- `tools/BattleRl` 直接编译链接 `Assets/Logic`；JSON-lines 持久规则进程提供 reset/step、真实结构状态、45维向量、33项语义动作与合法掩码。当前声明版本只包括双032敌、阿瑞希亚等级2本人炽热剑术、原行进和狂怒、红蓝各1晶的小牌库演练。
- 合法动作通过 `DemoStateCheckpoint` 对真实正式入口预执行并恢复；检查前后状态和原牌/敌实例不变。只缓存声明范围的完整状态键，不手写费用/护甲/时机模拟规则。未合法则拒绝执行；不支持更大范围明确报错。
- `train_ppo.py`：45→64共享tanh、33项masked actor与标量critic，PPO clip0.2、GAE0.95、gamma0.97、Adam、熵正则、梯度裁剪。复用本地NumPy，在CPU训练。没有下载大体积CUDA框架。
- `validate_replay.py`：重新载入保存的PPO模型，逐步验证同一语义选择和前后实际状态，并验证非法动作拒绝不污染战斗；有限差分验证实际 PPO/critic/entropy 梯度。
- `build_pve_rl_replay.py`：将模型输出转换成原卡点击→模式→确认、实际敌实例、原技能、逐攻击来源分配等UI动作；生成每个动作的前后状态断言与映射。复用既有场景自动化，不设置场景内部状态、不注入获胜结果。
- `environment.json` 记录有序特征与动作目录；原卡/敌元数据及归属可核查。流程使用文档见 `tools/BattleRl/README.md`。

## 速度和算力判断

本小型环境按实测线性外推：100万步约14.9分钟、1000万步约2.48小时，**仅在同样的动作成本和缓存命中条件下成立**。这不是全卡库估时。更广泛的未见状态需要做正式规则预检，反射恢复和组合候选会提高CPU成本，应先分别测冷/热掩码与IPC再扩大训练。

当前更新仅1.4秒，使用更强GPU并不能解决占主要耗时的真实状态采样；第一阶段本机CPU已经足够，暂无增加算力需求。后续更大PPO网络、批量环境需要时可以换CUDA训练器，继续用同一规则协议，不重新实现游戏。

## 限制与下一批

200个新种子仅改变同一战斗家族的手牌顺序，不是200种不同敌群。当前模型不是完整游戏策略，不能宣称跨英雄、随机标准手牌、怪物抗性或全部卡牌泛化。胜利也不能证明规则正确：RL与掩码都调用同一后台，需继续原规则独立预期与UI状态断言。

下一批按真实依赖增加敌人/资源/手牌组合，加入原16牌实际抽到的战斗检查点、部队耗竭及攻击来源，记录构筑种子和实体；测试集按完整构筑/敌群留出，不只换seed。动作不宜将所有卡牌选择暴力展开，应逐步扩展模式/目标/材料分层及对应合法掩码；新增范围先后台通过，最终继续Unity回放。保留随机合法探索做覆盖补充，避免只看赢家遗漏失败路径。
